# 三套 AI 交易系统横向对比

对比对象：

| 代号 | 项目 | 技术栈 | 规模 |
|---|---|---|---|
| **A** | `AI-Trading-System-v9.0.6-INIT` | Python，Flask 看板 | 114 个 py / 22,438 行；核心交易 34 文件 / 10,805 行 |
| **B** | `quantbot-main` | Go + Wails 桌面 + React | 296 个 go / 123,647 行（`internal` 约 100,205）；前端 26 tsx / 15,495 行 |
| **我方** | `easy-stock` 交易智能体 | Go 服务 + React 前端 | trading 包 49 文件 / 18,533 行；前端 trading 4,115 行 |

对比方法：**只认代码事实，不认 README 宣称**。每条结论都落到 `文件:行号`。
统计口径：核心能力以「下单路径上是否真的被执行」为准，不以「函数是否存在」为准。

---

## 一、结论先行

| 对手 | 判断 | 一句话理由 |
|---|---|---|
| **对 A** | **全面领先，且不在同一层级** | A 的核心宣传功能约一半是死代码或静默失效：创业板/科创板止损档位实际不生效、B 级风控三条永不触发、经验闭环没有调用者、账本实测差 49,006 元且对账未接入、无券商通道、无滑点无手续费。它是一个能跑的演示原型。 |
| **对 B** | **各有所长，方向不同** | B 的「研究带宽」比我们厚：55 个工具、5 角色智能体 + 对抗式评审、真回测引擎（含冲击成本与基准）、8 因子选股、组合优化、账本四账对平。我们的「执行与约束的诚实度」比 B 厚：撮合真实化、止损体系真的会动、失效条件可执行、冷静期、置信度校准、沙盘回放。 |
| **共同短板（对我方）** | **缺系统级回测，是我方唯一的大件功能缺口** | B 有历史重放 + 绩效指标 + 参数网格；A 有因子级向量回测。我方只有「同一决策点的沙盘回放」，没有跨时间的历史重放。 |

**最重要的判断**：B 的问题比 A 更值得警惕，因为它「看起来什么都有」——
移动止损、时间止损、止盈、风险预算公式、实盘通道，代码里全都能搜到，
但**移动止损和时间止损是死代码**（状态每轮被重置）、**止盈只发告警不执行**、
**日决策主链路在实盘模式下仍只记账不下单**、**实盘成交回报会二次计费**、
**波动率是 `volatility * 1.1` 编的、Agent 置信度由迭代次数拼出来、
Planner 文案硬编码「已分析 4,862 支 A 股」**。
这类「有实现但没生效」比「完全没有」更危险——它让人以为风险被管住了。

## 二、九维对比矩阵

| 维度 | A（Python） | B（quantbot） | 我方 | 谁更强 |
|---|---|---|---|---|
| **模型使用** | 4 个调用点，纯文本 + JSON 模式，**无 function calling**，数据全靠 Python 预拼进 Prompt | 约 16 个提示词入口，**55 个工具 + function calling**，5 角色分工 + 异议官/多空辩论/集成投票 | **1 处模型调用**，12 个工具，单智能体，工具循环受限 | **B**（研究带宽） |
| **提示词上下文** | 持仓、板块、龙头、经验层、因子层（约 3k tokens） | regime、六维、组合快照、回撤、风控摘要、候选 Top-N、共识、沪深300 ground truth | 持仓论点/失效条件/预期天数/已持有/入场环境/置信度/复核次数、冷静期、记忆、校准、计划差异 | 相近，各有取舍 |
| **止损体系** | 档位有 bug：`sz300xxx`/`sh688xxx` 全按 -5%；B 级三条永不触发 | 初始/ATR 止损**真执行**；**移动止损与时间止损是死代码**（peak/openDate 每轮重置）；止盈只告警 | ATR 分档止损（受 `MaxStopLossPercent` 约束）、移动止损只上移不下移（SQL `WHERE stop_loss_price<?` 保证）、时间止损、失效条件触发减仓 50% 且 `auto_reduce_at` 只执行一次 | **我方** |
| **仓位定价** | Score 分档 × Mood × Winrate；**单笔风险约束不存在**；无历史胜率时固定放大 1.1 倍 | 组合优化权重 × 现金；「风险预算÷止损距离」**只是个可选工具**，下单不强制 | `0.5+0.5×confidence` 再乘 ATR 项 `clamp(2.5/ATR%,0.55,1)`，两个系数**只减不增**；定价导致不足一手时按一手执行 | **我方** |
| **撮合真实度** | 按最新价瞬时全额成交，**无滑点、无手续费、无部分成交** | 即时全额、零滑点；有佣金万三+最低 5 元、卖出印花税、单笔不超成交额 8%；>5000 股跨周期拆单 | 滑点按成交额分档 0.30%/0.15%/0.05%、单笔不超成交额 0.5%（超出部分成交）、涨停买/跌停卖不成交、部分成交比例由 `FNV(order.ID)` 确定性抖动、成交额缺失按最冷档 | **我方** |
| **成本控制** | 每 90 秒必调一次模型（无变化检测） | 定时任务必调，无变化检测 | 变化检测指纹 + 20 分钟窗口，什么都没变就不调；事件通道（单票跌 5%/板块资金转负/组合 15 分钟跌 1.5%）才临时加轮，带频率上限 | **我方** |
| **记忆与学习** | 复盘/禁忌会注入；**交易结果从不回写**（`thesis_outcomes`=0），所谓自进化断裂 | 研究记忆只给前端看，**不进任何 prompt**；Feedback 采集了但不进主张 prompt | 平仓自动生成记忆（每轮 tick 同步，无需等复盘），按同标的 +3/同行业 +2/同状态 +1 排序，超 3 月丢弃，最多 8 条；置信度校准（分桶真实胜率 + Brier，样本 ≥30 才进提示词） | **我方** |
| **验证能力** | 因子级向量回测（OOS 不参与转正，Sharpe 8.57 但回撤 -47%，数字不可信）；**无系统回测** | **真回测引擎**：停牌不成交、涨跌停、Almgren-Chriss 冲击成本、基准 Alpha/Beta、参数网格（仅单标的） | 沙盘回放（同快照同建议只换阈值，纯读，逐笔给原因）；**无历史重放** | **B**（回测）／我方（决策回放） |
| **账本可靠性** | JSON 主账本 + SQLite，**实测差 49,006 元**，`audit_engine` 从未被调度 | 现金/持仓可由成交流水重建 + 四账对平 + 单测 | 健康接口暴露 `ledger.drift`，自愈对账每轮跑，当前实测 drift=0 | 我方 ≈ B ＞ A |
| **实盘通道** | **占位符**（`ai_executor.py` 打印一行就 return True） | 有 Ptrade/QMT 网关，但**日决策主链路不下券商单**，且成交回报二次计费 | 参考适配器 + 受理/成交分离 + 累计成交增量对账 + fail-closed 门控（缺配置拒绝启用）；假券商 8 用例覆盖全链路 | **我方**（B 有真实厂商对接但主链路断开） |

## 三、我方明确领先的六件事（都可指向代码）

1. **失效条件可执行化**：模型买入时写下「什么情况下我判断错了」，代码按 `price_below/price_above/sector_flow/deadline_days` 判定，触发减仓 50%，`auto_reduce_at` 保证只自动执行一次。A 与 B 都没有这个概念。
2. **止损冷静期**：同标的 4 小时、同板块当日亏 2 次即禁买，从 `trading_closed_trades` 推导，不另建表；按交易时段累计（跳过午休/隔夜/周末），回看窗口按最坏自然跨度放大。两者都没有。
3. **置信度校准**：分桶统计真实胜率 + Brier 分数，样本 ≥30 才写进提示词，flat 与未填单列。A 的 `thesis_stats` 是空表，B 的置信度是「迭代次数 + 工具调用数」拼出来的伪指标——**两边都没有校准**。
4. **沙盘回放**：同一快照 + 同一模型建议，只换交易风格阈值，回答「换成稳健会怎样」，纯读、逐笔给差异原因。两者都没有。
5. **撮合不撒谎**：三个乐观来源（滑点偏小、成交量大、涨跌停照样成交）逐个堵住，部分成交用确定性抖动保证可复现。
6. **实盘通道的失败安全**：缺任一配置就拒绝启用并记 error，「半套配置比没有配置更危险」写进了实现。

## 四、我方明确落后的四件事（按缺口大小排序）

### 4.1 没有系统级回测引擎（最大缺口）

我方只有「同一决策点的沙盘回放」，没有「历史时间轴重放」。
缺的具体是：历史逐日重放、绩效指标（年化/夏普/最大回撤/胜率/盈亏比）、基准对比、参数网格。

可复用资产很多：撮合的滑点分档模型、涨跌停判定、`marketrule` 的板块涨跌幅、`universe` 的候选池打分、`guard` 的止损链——都是纯函数，喂历史数据就能跑。**这不是从零造，是把已有的判定链串成时间轴**。

### 4.2 工具带与研究带宽

12 个工具 vs B 的 55 个。差距不在「能不能查」，而在我方工具集中在「价格结构 + 五类市场情报」，缺：财务指标、行业对比、股东/解禁、盈利预测、ETF/可转债联动。

### 4.3 决策的多角色对抗

我方是单智能体 + 受限工具循环。B 有 5 角色分工，且在同一决策内串行做「前置研判 → 主张 → 异议官 → 多空辩论 → 集成投票 → Kelly 缩放」，姿态门控**只降不升**。

代价要说清楚：多角色 = 多次模型调用。我方刻意保持 1 处调用是为了成本和可解释性。若要做，应当是「只在结论接近阈值时触发异议官」，而不是每轮五角色。

### 4.4 因子选股与组合优化

B 有 8 个 Barra 风格因子（value/quality/momentum…）+ IC + 因子健康度 + 动态权重，以及均值-方差组合优化（真实 90 日协方差，取不到降级等权）。
我方候选池是「门槛 + 打分 + 分散约束」，没有因子暴露控制，也没有组合层优化。

## 五、建议的补齐顺序（按性价比）

| 优先级 | 事项 | 理由 | 预估工作量 |
|---|---|---|---|
| **P0** | 系统级回测引擎 | 唯一的大件功能缺口；判定链都是纯函数，复用成本低；没有它，「这套东西到底行不行」只能靠实盘试错 | 中 |
| **P1** | 因子化的候选池上游 | 现有候选池只有门槛与合成分，没有风格暴露控制；B 的 8 因子 + IC 是成熟参考 | 中 |
| **P2** | 阈值贴近时的异议官 | 只在「结论接近阈值」时多调一次模型，成本可控；B 的「只降不升」门控值得直接借鉴 | 小 |
| **P3** | 工具带扩充（财务/解禁/股东） | 提升调研质量，但不改变判定结构 | 小 |

**不建议照搬**：B 的多角色全量并行（成本高、责任分散）、A 的双线程高频调用（90 秒一次，无变化检测，纯烧钱）。

## 六、方法说明与边界

1. 本对比基于**静态代码审阅**，不是跑分或实盘对照。所有数字来自代码与数据文件实测，不是估算。
2. 「实现深度」分四档：**真代码强制**（下单路径上会被执行）／**部分**（有代码但条件不满足）／**仅提示词**／**无**。判定以「会不会真的发生」为准。
3. 两个对手都是开源项目，代码里存在明显未完成痕迹。A 的核心交易代码**零测试**；B 有 144 个用例但**无 CI**，且有约 8,967 行近逐字节副本（`plannerhost`/`marketsixdim`/`intelligence`/`opensource`），存在改一处漏一处的双实现漂移风险。
4. 我方也不是完整体：实盘适配器仍缺真实券商凭证与厂商文档；校准与记忆的样本只能随真实交易积累；工具带 12 个 vs B 55 个是事实差距。
