# 外部项目评估：AI-Trading-System v9.0.6-INIT（本地完整版）

评估对象：`D:\quantbot-main\AI-Trading-System-v9.0.6-INIT`
评估时间：2026-10-20
评估目的：判断能否用于 easy-stock AI交易员

## 一、结论

**它是此前 GitHub 项目 `51ijjkbghvhj/ai-quant-trading-system` 的完整初始化版**，比发布版多出三块：`factor_lab`（因子工厂，含 203MB 全市场日线）、`audit_engine`（盘后对账）、`fundamental_risk_layer`（基本面风险标签）。

判断：

- **思路有可取之处**：盘后对账、因子生命周期（testing→active→decaying→retired）、因子注入提示词，这三个机制我们的设计里还没有；
- **工程与统计仍不达标**：JSON 文件账本、无测试、经验层关键表实际为空、统计口径不严谨；
- **许可**：上游 GitHub 仓库为 MIT；本地 INIT 副本根目录没有 LICENSE 文件，来源与授权需确认。即便 MIT，也只建议参考思路，不建议逐行搬运。

## 三、新增模块逐项分析

### 1. `factor_lab`：用 AI 挖因子，回测后注入提示词

流水线（`scheduler.py`，每日 17:00）：

```text
akshare 拉全市场日线 → 存 parquet（203MB）
  → 研究 AI 生成 2 个因子假设（带历史去重）
  → 向量化回测（T+1 开盘买入、持有 3 日、成本 0.13%）
  → 样本内 / 最近 3 个月样本外
  → 达标晋级 ACTIVE，否则留在 TESTING
  → ACTIVE 因子拼进交易 AI 的提示词
```

因子生命周期（`factor_manager.py:15-23`）：

| 状态 | 进入条件 |
| --- | --- |
| testing | 新生成 |
| active | 胜率 >51% 且 Sharpe >0.5 |
| decaying | 近 30 天胜率 <45% |
| retired | 近 30 天胜率 <35%，或 decaying 超 30 天 |

**做得对的地方**：用 T+1 开盘价买入，避开了"当日收盘价买入"的未来函数；有样本外切分；有最小样本量（50）；有因子去重；有退役机制。这几条比多数"AI 选股"脚本严谨。

**问题**：

1. 胜率按**信号条数**统计，同一只股票连续多日触发会被当成多笔独立样本，存在严重自相关；
2. 没有剔除市场 beta：上涨行情里"持有 3 日"的胜率天然高于 50%，因子可能只是"市场上涨"的代理；
3. Sharpe 用 `sqrt(252/3)` 年化重叠样本（`backtester.py:127`），数值虚高；
4. 最大回撤阈值对 Sharpe>1.5 的因子放宽到 **-98%**（`backtester.py:154`），等于关闭该项检查；
5. 无亏损时 `profit_factor` 返回 `inf`，会污染排序；
6. 样本外只有 3 个月、阈值仅 48%，与样本内同分布，验证力度有限；
7. 公式执行用 `df.eval` + 字符白名单（`backtester.py:73-79`），允许 `.` 与字母，仍建议改为 AST 白名单，禁止属性访问与 `__`；
8. **注入方式有问题**：注入给交易 AI 的是"请寻找满足 `close < boll_lb and rsi_14 < 30 ...` 形态的股票"，而不是由代码先算出当前命中名单。这等于让模型再做一次全市场扫描，幻觉与漏选都无法避免。

结论：**生命周期值得学，统计口径与注入方式不能学**。

### 2. `audit_engine`：盘后账本对账

`audit_engine.py` 做了一件正确的事：**不信任存下来的账，按交易流水重算一遍**。

```text
calc_cash = 初始资金 + Σ卖出金额 - Σ买入金额
calc_pos  = FIFO 重放所有交易后的持仓成本
与 portfolio.json 中的 cash / positions 比较，差异 <1 元视为通过
```

这正是"账本可查"的底线能力。但实现有明显缺口：

- 完全忽略佣金与印花税（`amt = price * qty`），一旦账本记了费用就必然对不上；
- 不处理 T+1、分红送转、除权；
- 是一个独立脚本，不在交易链路里，也没有触发告警或停机；
- 对账结果只打印，没有落库。

结论：**机制必须做，实现要重写**。

### 3. `fundamental_risk_layer`：异步基本面标签

后台线程调用同一个模型配置，给持仓与关注池打"基本面风险标签"，结果只作为 AI 的背景信息，**不参与风控否决**。非阻塞、线程安全字典、异常不穿透主循环——这三点处理得对。

问题：让 LLM 直接判断"基本面风险"，而输入并不包含财报原始数据，本质是模型先验；标签没有明显的过期与刷新策略；无速率限制。

结论：可以保留"异步背景层"的形态，但标签必须来自可核对的数据（公告、财报字段），不能由模型凭空生成。

## 四、真实运行数据说明了什么（最关键）

本地 `trading_history.db` 不是空壳，有真实运行痕迹，正好可以检验"经验层"是否真的有效：

| 表 | 记录数 | 说明 |
| --- | --- | --- |
| `trade_execution` | 61（37 买 / 24 卖） | 时间跨度 **2026-05-22 ~ 05-27，仅 5 个交易日** |
| `ai_analysis` | 647 | AI 决策记录 |
| `risk_control` | 100 | 风控事件 |
| `thesis_stats` | 21 | 胜率统计 |
| `thesis_outcomes` | 27 | 单笔 thesis 结果 |
| `daily_reflection` | 16 | 每日复盘 |
| `pattern_memory` | 52 | 形态记忆 |
| **`ai_mistakes`** | **0** | README 主打的"错误记忆" |
| **`feature_store`** | **0** | 特征存储 |

三个硬事实：

1. **`ai_mistakes` 一条都没有**。README 说"每日自动复盘沉淀 Mistakes，次日盘前自动注入，拒绝重复踩坑"，但在 61 笔真实成交、5 个交易日的运行里，这张表是空的。宣传与实现不一致。
2. **`thesis_stats` 的 key 是自由文本**，例如 `"创业板活跃标的，+17.4%领涨，板块强"`，`total_trades=1`、`win_rate=1.0`。21 行里绝大多数是 n=1 的"100% 胜率"，无法聚合、无法比较、无法指导决策。只有 `General` 一组有 7 笔（85.7%）勉强可用。
3. **`daily_reflection` 有 16 条但只有 5 个交易日**，还出现 `2025-05-15` 这样的异常日期（其余是 2026-05），说明日期解析与去重都有问题。

结论：这套"经验层"能跑通流程，但**产出的东西不可用**。根因不是模型，是数据建模：用自然语言当统计维度、样本量没有下限、写入没有幂等。

## 六、对我们 P2 / P4 的增量

### P2 增加两项

1. **每日账本对账（reconcile）**：按 `trading_fills` 重放现金与持仓，**包含佣金、印花税、过户费**，与账户表比对；差异 > 0.01 元即落库告警并**暂停自动交易**。比 INIT 版更严：它是脚本 + 打印，我们要做成链路内的硬校验。
2. **cycle 完整性校验**：一轮 cycle 必须同时具备市场快照、候选池、prompt hash、模型原文、逐条风控裁决；缺任何一项标记 `incomplete`，不允许进入执行阶段。

### P4 经验层必须换口径

1. **维度规范化**：`thesis_type` 用枚举（低吸/突破/趋势跟随/事件驱动/龙头接力），市场阶段用已有 `phase`，再叠加板块与持仓天数区间；**禁止自由文本当 key**。
2. **样本下限**：单个维度 <30 笔只输出"错误清单"，不输出胜率；不展示 n=1 的 100%。
3. **写入幂等**：按 `(trade_date, decision_id)` 唯一约束，防止重复复盘。
4. **因子与交易经验分离**：若未来做因子，必须样本外验证、去重、退役，并且**由代码先算出当前命中名单**再交给模型，绝不让模型自己"找符合形态的股票"。

## 七、明确不采纳

| 项 | 原因 |
| --- | --- |
| 把 LLM 当因子挖掘器 | 缺少统计训练与多重检验校正，容易产出过拟合公式 |
| MDD 阈值 -98% | 等于关闭风险检查 |
| 用信号条数当样本 | 自相关，胜率虚高 |
| 自由文本当统计维度 | 无法聚合，n=1 的 100% 会误导决策 |
| JSON 文件账本 | 无事务、无并发保护 |
| 203MB parquet 入库 | 数据文件不应进代码仓库 |
| 直接把"符合形态"的公式丢给模型 | 模型会重新全市场扫描，幻觉不可控 |

## 八、总体判断

三个参考项目各自的定位很清楚：

- **QuantBot v1.8**：架构最完整（真实券商桥、硬门控、决策链、审计），但许可证禁止商用，只能"看架构、自己写"；
- **AI-Trading-System INIT**：机制上有两个真东西——**盘后对账**与**因子生命周期**，但统计口径与数据治理不达标，且实际运行数据证明其经验层尚未产出可用结论；
- **GitHub 发布版**：同一项目的精简版，价值主要在文档与反面教材。

对我们要做的 AI 交易员，这三份材料拼起来正好回答了三个问题：**架构长什么样（QuantBot）、账本怎么自证（INIT）、哪些做法看起来聪明其实是幻觉（两者都有）**。
