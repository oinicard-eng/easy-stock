# AI 交易员：目标架构与实施契约

> 本文是对当前 P1（计划生成 + 人工确认）的升级设计。P1 是"工具"，目标是"交易员"：自动选股、自动分析市场、自动买卖、自动复盘、自动积累经验，全程可观察、可审计、可回放。

## 一、现状与目标的差距

| 能力 | P1 现状 | 目标 | 差距性质 |
| --- | --- | --- | --- |
| 市场认知 | 模型自行从快照里"感觉" | 代码算出情绪阶段、宽度、赚钱效应、板块强度、指数趋势，模型只解读 | 缺确定性认知层 |
| 选股 | 人工填关注池 | 全市场硬过滤 → 候选池 ≤30（带入选/剔除理由）→ AI 精选 | 缺筛选引擎 |
| 决策 | 单次生成计划 | 每轮循环产出信号，带 thesis/conviction/失效条件 | 缺循环与信号模型 |
| 执行 | 人工点确认 | 自动执行（可开关），受限价/涨跌停/资金约束 | 缺调度与自动通道 |
| 持仓管理 | 无 | 防守线上移、分级止盈、强制退出、冷却期 | 完全缺失 |
| 复盘 | 无 | 收盘后逐笔归因、错误归档、thesis 胜率 | 完全缺失 |
| 经验 | 无 | 次日把错误与胜率注入提示词 | 完全缺失 |
| 可观察 | 只有计划详情 | 每轮：市场认知 → 候选池 → 模型原文 → 风控逐条裁决 → 成交 | 缺决策日志与回放 |

结论：P1 的账本、风控校验、模拟撮合、Broker 接口可以保留；缺的是**认知层、筛选层、调度层、持仓生命周期、复盘经验层、决策日志**。

## 二、目标架构

```text
┌──────────────── 每轮循环（默认 3 分钟，事件可提前触发）────────────────┐
│                                                                        │
│  1 市场认知(确定性)   现有 marketemotion：情绪分/阶段/宽度/风险分        │
│         ↓             指数趋势、板块强度、涨跌停、连板高度              │
│  2 候选池(确定性)     流动性/可交易性硬过滤 → ≤30 只，带入选与剔除理由   │
│         ↓                                                              │
│  3 上下文组装         账户、持仓、防守线、冷却名单、经验摘要、方法论片段 │
│         ↓                                                              │
│  4 AI 决策(LLM)       输出信号：BUY/SELL/HOLD + score + conviction      │
│         ↓             + thesis + 失效条件 + 触发价                     │
│  5 风控裁决(确定性)   S 级一票否决 → A 级仓位/次数 → B 级技术退出       │
│         ↓                                                              │
│  6 执行(模拟)         限价/市价撮合、T+1、涨跌停价、资金校验             │
│         ↓                                                              │
│  7 记账               订单、成交、持仓、现金（单事务）                   │
│                                                                        │
└───────────────┬────────────────────────────────────────────────────────┘
                │ 收盘后
                ↓
     8 复盘(代码算事实 + AI 归类)  → 9 经验库 → 次日注入第 3 步
```

### 关键分工（不可让步的三条）

1. **认知不让模型算**。情绪阶段、宽度、赚钱效应由 `marketemotion` 与行情统计得出，随快照一起落库。模型看到的是"情绪分 38、阶段退潮、上涨家数 1240/下跌 3520、涨停 21 家、跌停 9 家"，而不是"今天感觉不太好"。
2. **选股不让模型全市场扫**。模型只能在候选池内排序。候选池的每一条入选/剔除理由都要落库，否则无法解释"为什么没买某只票"。
3. **风控不在模型里**。风控是独立裁判，优先级永远最高；模型输出再漂亮，S 级规则可以直接覆盖成 HOLD 或 SELL。

## 三、每轮循环的契约

### 状态机

```text
pending → observing → screening → deciding → judging → executing → settled
                 ↘ error（任一步失败都落库，不静默丢弃）
```

- 单飞：同一账户同时只允许一个循环在跑（`running` 唯一约束）。
- 幂等：同一 cycle 的执行阶段重入不会重复扣款（订单状态机保证）。
- 崩溃恢复：启动时把 `observing/deciding/executing` 的 cycle 标记为 `interrupted`，不自动续跑，避免半截状态。

### 每轮必须落库的字段

```go
type Cycle struct {
    ID, AccountID string
    Phase string                     // observing/screening/deciding/judging/executing/settled/error
    Market  MarketView               // 情绪分、阶段、宽度、涨跌停、板块 Top5、指数涨跌
    Universe []Candidate             // 每只：symbol, score, 入选理由, 剔除原因
    PromptHash string
    PromptTokens, CompletionTokens int
    Model, Runtime string
    AISummary string                 // 模型原文摘要（保留原文 JSON）
    AISignals []Signal
    Verdicts  []Verdict              // 逐条：信号、S/A/B 命中项、放行/否决、理由
    Orders    []Order                // 实际下发与成交
    StartedAt, FinishedAt time.Time
    Error string
}
```

这条记录就是"可观察"的全部依据：任意一天任意一轮，都能回答"它看到了什么、选了谁、为什么买、谁否决的、成交没有"。

## 四、市场认知层（确定性）

复用并扩展现有能力，输出固定结构：

| 维度 | 数据来源 | 用途 |
| --- | --- | --- |
| 情绪分/阶段 | `marketemotion.Snapshot`（已有） | 决定仓位上限、是否允许开新仓 |
| 盘中宽度 | `marketemotion.IntradaySnapshot`（已有） | 退潮期收紧、冰点期只做低吸 |
| 涨跌停与连板高度 | 现有 `limit-up-ladder` | 判断赚钱效应与接力风险 |
| 板块强度 Top5 | `themeindex` / `sectorflowsample` | 候选池加权，避免逆势选股 |
| 指数趋势 | 现有 K 线 | 20 日线上下决定总仓位上限 |

输出示例（落库并注入提示词）：

```json
{"emotion_score":38,"phase":"退潮","breadth":"weak","up":1240,"down":3520,
 "limit_up":21,"limit_down":9,"max_streak":3,"index_trend":"below_ma20",
 "top_sectors":[{"name":"银行","strength":72}],"position_cap":0.5,
 "new_position_allowed":true,"reason":"退潮期仅允许评分≥85的低吸"}
```

## 五、候选池（确定性筛选）

三段式，每段都记录理由：

1. **硬剔除**：ST、停牌、上市 <60 日、日均成交额 <1 亿、现价触及涨跌停、股价 <2 元、北交所（可配置）。
2. **打分**：量比、换手、5/20 日相对强度、板块强度、距 20 日线位置、近 5 日振幅。
3. **截断**：按分数取前 30，持仓与关注池强制保留（保证能管理已有仓位）。

模型只在这 30 只里做选择；若模型输出池外标的，直接判为无效信号并记录（这一条已经在 P1 的风控里实现）。

## 六、风控体系（独立裁判）

| 级别 | 规则 | 动作 |
| --- | --- | --- |
| S1 | T+1：当日买入不可卖 | 否决卖出 |
| S2 | 跌停不可卖、涨停不可买 | 否决 |
| S3 | 硬止损：主板 -5% / 创业板 -7% / 科创板 -8% | **强制 SELL，覆盖 AI** |
| S4 | 动态防守线被击穿 | **强制 SELL，覆盖 AI** |
| S5 | 单日亏损达到 -3%（可配置） | 当日停止开新仓（熔断） |
| S6 | 连续 3 笔止损 | 暂停自动交易，转人工 |
| A1 | 单票 ≤15%（龙头 ≤20%，绝对 ≤25%） | 缩减或否决 |
| A2 | 总仓位 ≤ 情绪阶段对应上限（50%~90%） | 否决 |
| A3 | 单日交易次数 ≤6 | 否决 |
| A4 | 冷却期：止损后 30 分钟内禁止再买同一标的 | 否决 |
| A5 | 分级止盈：+10% 卖 1/3、+15% 再卖 1/3、+20% 清仓 | 强制 SELL |
| B1 | 跌破 5 日线且板块强度 <40 | 建议卖出（模型可覆盖，需写理由） |
| B2 | 持仓超过 7 个交易日且无盈利 | 建议退出 |

S 级与 A5 的执行**先于**模型调用：先处理持仓退出，再让模型决定新开仓，避免"该卖的被模型拖着不卖"。

## 七、自动交易的安全边界

自动化不等于无约束，以下全部是硬开关：

1. **总开关**：`auto_trade_enabled`（默认关闭），开启需二次确认并记录操作人/时间。
2. **交易时段**：仅 09:30–11:30、13:00–14:50 开新仓；14:50 后只允许卖出。
3. **单日限额**：最多 6 笔、单日最大亏损 3%、单笔最大 25% 仓位。
4. **熔断**：触发后当日不再开仓，页面顶部红色提示，需手动解除。
5. **只做模拟盘**：`Broker` 默认 `PaperBroker`；实盘通道未实现且调用即报错。
6. **停止即生效**：关闭开关后，正在跑的 cycle 在"执行"阶段前终止，不产生新订单。

## 八、复盘与经验（收盘后）

复盘不是让模型写总结，而是先算事实、再让模型归类：

1. **代码算事实**：每笔成交的盈亏、持仓分钟数、最大浮盈/回撤、防守线是否被击穿、thesis 是否成立、是否违反过风控建议。
2. **AI 归类**：把当日所有交易与"未执行的信号"一起给模型，要求输出 `mistakes[]`（错误类型、触发条件、改进规则）与 `thesis_stats` 更新建议，**禁止编造数字**（数字由代码提供）。
3. **写入经验库**：

```sql
trading_experience(
  id, trade_date, thesis_type, market_phase,
  trades, wins, losses, avg_pnl, avg_holding_minutes,
  mistake_code, mistake_text, rule_text, importance, expires_at
)
```

4. **次日注入**：取 `importance > 0.6` 且未过期的 3 条错误 + 对应 thesis 类型胜率，拼进提示词第 3 步。经验必须有有效期，避免旧结论永久污染。

## 九、可观察性（前端）

新增「交易员日志」页，按时间倒序展示每轮 cycle 卡片：

```text
[14:32:10] 退潮 · 情绪 38 · 上涨 1240/3520 · 涨停 21
  候选池 28 只（剔除 312 只，主要：成交额不足 187、涨停 43、ST 21）
  AI：买入 600000.SH 目标 8%（score 82, conviction 71）
      理由：…  失效条件：…
  风控：通过（A1 8%<15%，A3 当日第 2 笔）
  执行：限价 9.72 未触及 → 挂单
  ── 展开可看模型原文、完整 prompt hash、token 消耗 ──
```

每张卡片可回放到当时的市场快照，便于事后判断"是模型错还是数据错"。

## 十、分阶段交付与验收

| 阶段 | 交付 | 验收标准（可运行、可复现） |
| --- | --- | --- |
| **P2 闭环骨架** | 循环调度、市场认知、候选池、AI 决策、风控裁决、自动执行、决策日志页、熔断开关 | 一次完整 cycle 全字段落库；页面可回放；关闭开关后不产生订单；熔断触发后不再开仓 |
| **P3 持仓管理** | 防守线、分级止盈、强制退出、冷却期、thesis 三态 | 构造价格序列单测：防线上移不回撤、+10/15/20% 分批卖出、-5% 强制卖、止损后 30 分钟拒绝再买 |
| **P4 复盘经验** | 收盘复盘、错误归档、胜率统计、次日注入 | 连续 5 个交易日样本后，经验表有数据且次日 prompt 中可见；数字与账本一致 |
| **P5 实盘** | Broker 实现、双人确认、单日限额、审计日志 | 不实现前，任何调用返回 `ErrBrokerUnavailable` |

## 十一、需要提前说清的代价

1. **成本**：90 秒一轮、每天 4 小时 = 160 次模型调用，按单次 3k–8k token 估算，日成本远超收益验证所需。建议 **3 分钟基线 + 事件触发**（持仓触及防守线、情绪阶段切换、候选池新增强势股），约 30–40 次/日。
2. **延迟**：LLM 单次决策 5–30 秒，做不了打板与秒级套利，适合低吸、波段、趋势跟随。这一点必须写进产品定位，否则会被误用。
3. **样本**：复盘胜率在 30 笔以内没有统计意义，经验层早期只用于"避免重复错误"，不用于放大仓位。
4. **数据**：全市场实时筛选依赖现有行情接口的稳定性；接口降级时必须停止开新仓，而不是拿旧数据硬跑。

`docs/research/ai-quant-trading-system-review.md` 已确认：该项目的代码不可直接接入（执行是占位、账本是 JSON、无测试）。其可借鉴的四点——动态防守线、分级止盈、持仓生命周期、经验回灌——已分别落入本文第六、八节与 P3/P4 阶段。

## 十三、P2 范围修订（参考 QuantBot v1.8）

`docs/research/quantbot-review.md` 核对后，P2 增加五项已被验证的必要设计：

1. `decision_id` 贯穿决策 → 订单 → 成交 → 复盘，否则亏损无法归因到判断；
2. `reserved_cash`：下单即冻结资金，撤单释放，杜绝多笔挂单重复占用同一笔钱；
3. 门控拆分：`pause_buying`（只拦买、放行卖）与 `kill_switch`（全停）分离；
4. 输出守卫：模型输出除结构校验外，还要校验权重上限、枚举、标的格式与越权字段；
5. 盘前补跑：启动时若当日无盘前 cycle，补跑一次并标记 `catch_up`。

注意：QuantBot 使用 PolyForm Noncommercial 1.0.0 许可，**不得复制其代码**，只能按其公开行为独立实现。

补充（参考 AI-Trading-System v9.0.6-INIT）：

6. **每日账本对账**：收盘后按 `trading_fills` 重放现金与持仓（含佣金/印花税/过户费），与账户表比对；差异 > 0.01 元即落库告警并暂停自动交易。
7. **cycle 完整性校验**：市场快照、候选池、prompt hash、模型原文、逐条风控裁决缺任一项即标记 `incomplete`，不得进入执行阶段。

经验层口径（P4）见 `docs/research/ai-trading-system-init-review.md` 第六节：维度枚举化、样本下限 30、写入幂等、因子与交易经验分离。
