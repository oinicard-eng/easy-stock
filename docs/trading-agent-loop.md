# 自动交易循环（P2.4）：调度、闸门与熔断

这一层解决的问题是：**判断已经可靠（P2.3），但谁来按时发起判断、按什么顺序拦、出错后怎么恢复。**

它只做编排，不碰规则。买不买、买多少仍然由 `policy` + `Decide` 决定；能不能开新仓由这里的闸门决定；成交由 Broker 决定。三层分开，任何一层出问题都能单独定位。

## 一、一轮循环的顺序

`Autopilot.RunCycle` 的顺序不可交换，每一道闸门都会写进 `Cycle.Gates`：

| 顺序 | 闸门 | 触发方式受限 | 被拦后 |
| --- | --- | --- | --- |
| 1 | `autopilot.enabled` 自动开关 | 仅自动触发 | `skipped`，不生成计划 |
| 2 | `session` 交易时段 | 仅自动触发 | `skipped`，不生成计划 |
| 3 | `gate.kill_switch` 账户总闸 | **全部** | `blocked`，不生成计划 |
| 4 | `cycle.quota` 当日轮次 | 仅自动触发 | `skipped`，防呆 |
| 5 | `gate.breaker` 当日熔断 | **全部** | 继续跑，但买入被整批剔除 |
| 6 | `gate.session_window` 尾盘 | 仅自动触发 | 继续跑，但买入被整批剔除 |

为什么人工触发能越过 1/2/4/6，却越不过 3/5：
- 时段、尾盘、轮次配额回答的是"什么时候做更划算"，人能判断，也常常需要在下班后复盘跑一轮；
- kill switch 与熔断回答的是"今天已经不能再亏"，这个事实不会因为人想再试一次而消失。

熔断与总闸是资本保护，不是偏好设置。这条边界写死在代码里，不做成配置项。

## 二、每轮具体做什么

1. 读配置、判闸门；
2. 读账户、确定/读取**当日基准权益**；
3. 熔断检查（用基准权益算日亏）；
4. **先撮合既有挂单**（`MatchPending`）——上一轮挂出去的单可能本轮才够条件成交，放在生成新计划之前，快照里的可用资金才是撮合后的真实值；
5. 生成计划（`RunPlanSync`，同步拿到结果，带 `cycle_id`）；
6. 自动执行（`auto_execute=true` 且计划为 draft 时立即撮合）；
7. 收盘权益复核，本轮成交后若刚好越过阈值，同轮标出熔断。

## 三、熔断器

| 代码 | 口径 | 状态 |
| --- | --- | --- |
| `daily_loss` | 当日权益相对**当日基准**跌 `max_daily_loss_percent`（默认 3%） | 已接线，可触发 |
| `stop_streak` | 连续 3 笔止损 | **未装弹**：止损成交链路在 P3，`StopStreak` 目前恒为 0 |

`stop_streak` 在界面上显示为「未接线」（虚线、半透明），而不是和日亏熔断一样显示「监控中」。把一条永远不会触发的规则显示成"已保护"，比没有这条规则更危险。

触发时的动作（三处同时写，缺一处就会出现自相矛盾的状态）：
1. `trading_day_state.breaker = daily_loss`（当日既成事实，供循环与复盘读）；
2. `trading_control.pause_buying = true`（账户现在不许买，人工生成的计划也受限）；
3. 记一条 `cycle.Breaker`，本轮买入被整批剔除并留下 `gate.breaker` 裁决。

**当日基准只写一次。** 若允许每轮刷新基准，日亏永远从零开始算，熔断就永远不会触发。

**熔断是当日事实，不随开关而消失。** 关掉自动循环再打开，熔断仍在；只能通过 `POST /api/v1/trading/autopilot/breaker/reset` 并附理由解除——这是唯一一处"人推翻机器保护"的入口。

## 四、崩溃恢复与幂等

| 场景 | 处理 |
| --- | --- |
| 进程在轮次执行中退出 | 启动时 `AbortRunningCycles` 把 `running` 标为 `aborted` 并补结束时间 |
| 进程在计划生成中退出 | 启动时 `AbortRunningPlans` 把 `running` 计划标为失败，避免界面永远转圈 |
| 同一时刻两次触发 | 进程级单飞：第二个调用返回 `ErrCycleRunning`（HTTP 409） |
| 计划生成期间人工又点生成 | 共用同一把单飞锁，人工请求返回「已有计划正在生成」 |

**幂等靠 cycle_id**：`Plan.CycleID` 与 `Order.CycleID` 都会落库，一笔成交可以沿着 `order → plan → cycle` 一路回到"哪一轮、什么闸门状态下做的"。

## 五、接口

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET | `/api/v1/trading/autopilot` | 配置、当日状态、熔断器清单、下一次调度 |
| POST | `/api/v1/trading/autopilot` | 部分字段更新（未传的字段保持原值） |
| POST | `/api/v1/trading/autopilot/breaker/reset` | 人工解除熔断，`reason` 必填 |
| GET | `/api/v1/trading/cycles?limit=` | 循环日志，新的在前 |
| POST | `/api/v1/trading/cycles/run` | 人工触发一轮（`trigger=manual`） |

## 六、验收记录（真实数据）

| 场景 | 结果 |
| --- | --- |
| 默认状态 | `enabled=false`、`auto_execute=false`、间隔 180s、日亏阈值 3%、开仓截止 14:50 |
| 关闭开关连跑 4 轮 | 全部 `skipped`，`trading_plans` 0 条新记录 |
| 人工触发（未开启自动执行） | `done`，4 笔建议通过、1 笔被拦，计划停在 draft，备注「自动执行已关闭」 |
| 人工触发（开启自动执行） | `done`，5 笔挂单全部成交，权益 99989.79 → 99964.49（手续费） |
| 熔断触发 | 阈值临时调至 0.02%，真实权益 -0.04% → `breaker=daily_loss`、`gate.breaker` 关闭、`pause_buying=true`、4 笔买入被整批剔除，日志写明「门控剔除全部 4 笔建议」 |
| 解除熔断无理由 | HTTP 400 |
| 解除熔断带理由 | 熔断清空，`pause_buying` 同步释放（仅解除熔断自己按下的暂停），原因写入 `breaker_detail` |
| 账本 | 熔断前后 `drift=0`，`reserved_cash=0`，无孤儿冻结 |
| 尾盘 | 21:39 人工触发时 `gate.session_window` 记录为「已过 14:50，人工触发允许开仓」 |
| 自动调度 | 非交易时段 tick 直接返回，不写循环记录（避免一天 80 条"没开盘"冲掉日志） |

单测覆盖（`autopilot_test.go`，8 个）：开关关闭不产生计划、人工越过开关但越不过总闸、日亏熔断落库并暂停买入、解除熔断必须给理由、循环与计划互相指认、尾盘闸门记录、单飞、崩溃恢复。

## 七、已知边界

1. **止损连败熔断未装弹**（P3）：需要止损成交记录才能算准，现在不用不可靠的数字凑条件。
2. **节假日未内置**：靠行情时间戳与交易时段粗判，节假日循环会空转（`session` 通过但模型会看到陈旧数据）。理由是硬编节假日表每年要维护、错一天就全盘停摆。
3. **多账户**：循环固定跑 `paper-main`。表结构已按账户维度设计，接入实盘时按 broker 维度扩展即可。
4. **调度精度**：15 秒检查一次，因此间隔 3 分钟的轮次实际落在 3:00–3:15 之间。用固定 3 分钟定时器会让开盘后的第一轮最多晚 3 分钟，而开盘三分钟是最贵的。
