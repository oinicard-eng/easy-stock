# AI交易员升级评估：哪些地方还不够「智能」

> 评估时间：2026-10-20｜基线：commit `70e2a31` 之后的交付版
> 方法：逐文件核对实现，只写有代码证据的结论；每条都标了文件与行号级依据。

## 一、结论先说

现在的系统是一个**闭环完整、但反馈稀缺**的 LLM-in-the-loop 智能体：

- 闭环完整：调研 → 计划 → 裁决 → 执行 → 防守 → 复盘 → 记忆，七段全通，无断点。
- 反馈稀缺：**它做的判断，几乎没有任何一条会回到下一轮的输入里**。
  被拦的原因不回灌、写下的失效条件不检查、自己的置信度不用于定价、
  止损出局后没有冷静期。所以它每 3 分钟都在"第一次做交易"。

一句话概括当前瓶颈：**不是模型不够强，是喂给模型的上下文和喂回模型的后果都太少。**

## 二、现状事实（可核对）

| 维度 | 现状 | 依据 |
| --- | --- | --- |
| 循环节奏 | 每 180 秒一轮，单日上限 40 轮 | `cycle.go:124`、`autopilot.go:412` |
| 每轮模型调用 | 调研 ≤4 次 + 计划 1 次 | `research.go:171`、`service.go:457` |
| 实测成本 | 某日 5 轮循环 / 11 次调用 / 110,228 tokens ≈ **2.2 万 tokens 每轮** | `/trading/timeline` 实测 |
| 工具带 | 6 个，全部是行情与板块维度 | `tools.go:83` |
| 提示词输入 | 账户、持仓、行情快照、市场环境、8 条历史经验、本轮调研 | `prompt.go:18` |
| 风控 | 确定性规则包 + 守卫，阈值全局统一（止损 10%、移动止损 6%、启动 4%、止盈 40/40） | `policy/policy.go:148`、`guard.go:39` |
| 撮合 | 按最新价全额成交，无滑点、无部分成交 | `broker.go:105` |
| 已定义未使用 | `CycleTriggerEvent`（事件驱动轮次） | `cycle.go:35` 全仓无引用 |

## 三、六处「不智能」，按严重度排序

### 1. 模型看不到自己上一轮被拦在哪（最贵的一个）

**现象**：`BuildPlanPrompt` 的输入结构里没有任何"历史裁决/被拦原因"字段。
模型每轮都重新推理，不知道上一轮它想买的三只票被行业集中度拦了两只。

**证据**：`prompt.go:18` 的 `PlanPromptInput` 只有 Account/Positions/Quotes/Watchlist/Rules/Profile/Horizon/Notes/Market/Board/Experience/Research。`Experience` 来自 `BuildLessons(closedTrades)`，即**只有已平仓结果**，不含"想法被否决"。

**代价**：这是可复现的浪费。实测 2026-10-20 的 16 份计划里，同一批机器人产业链标的被反复提交、反复在 `sector.weight` 被拦。模型不是判断错，是**不知道自己已经被告知过**。

**为什么优先**：修复成本几乎为零（多渲染一段文本），收益是直接减少无效轮次与无效 token。

### 2. `invalidation` 写了，但没有任何代码读它

**现象**：提示词要求模型为每笔交易写"什么情况说明判断失效"（`prompt.go:234`），这个字段也确实存进了订单与记忆（`risk.go:125`、`memory.go:178`）。但**持仓期间没有任何环节检查它**。

**证据**：全仓 `Invalidation` 只出现在三处——写入（risk.go）、存档（memory.go）、检索匹配（memory.go:357）。`guard.go` 完全不读。

**代价**：模型写"若资金流转正或跌破 9.2 则判断失效"，之后股价在 9.3 横盘两周、板块资金流早已反转，系统仍然只认那条固定的止损线。**判断失效 ≠ 价格止损**，现在两者被混为一谈。

**这是"智能体"与"规则程序"最本质的差别所在**：规则只能对价格反应，智能体应当对自己的判断是否成立反应。

### 3. 置信度只是一个存档字段

**现象**：模型每笔都给 `confidence`（0–1），系统做范围校验后存库（`risk.go:452`），然后——没了。

**证据**：`Confidence` 的唯一消费者是 `memory.go:190`（存进记忆文本）与 `guard.go:154`（保护性卖出写 0 并注明"不编一个 1.0"）。**它不参与仓位计算，也没有任何校准统计。**

**代价**：置信度 0.4 和 0.9 的建议，系统给一样的权重上限。更关键的是，**没人知道模型说 0.9 的时候是否真的更准**。没有校准曲线，置信度就是装饰。

### 4. 止损出局后没有冷静期

**现象**：一只票在 10:00 触发止损清仓，10:03 的下一轮它就重新出现在候选池里，模型完全可以立刻买回来。

**证据**：全仓 `cooldown` 只存在于 `alerting.go`（告警冷却），交易侧无任何"近期止损标的禁买"逻辑。

**代价**：这是散户最典型的亏损模式（报复性交易），而系统当前对它零防御。连续两次止损会触发 `stop_streak` 熔断，但熔断是**账户级**的——它拦的是当天所有买入，而不是"这只票/这个板块先别碰"。粒度不对。

### 5. 风控参数不随波动率、也不随市场状态变

**现象**：所有持仓共用一套防守参数：移动止损 6%、启动门槛 4%、止盈 40%/40%（`guard.go:39`）。市场环境判断（`cognition.MarketView`）只影响**总仓位上限**一项，不影响止损宽度、单票上限、行业上限。

**证据**：`prompt.go:49` 只取 `Market.MaxExposurePercent`；`guard.go` 的 `evaluatePosition` 入参没有 market。`RiskRules` 是常量表，不随 regime 变化。

**代价**：一个日波动 2% 的银行股和一个日波动 8% 的机器人概念股，用同一个 6% 移动止损。前者永远打不到、后者开盘就被洗出去。同时"恐慌"环境下行业上限仍是 45%，等于跌的时候还允许半仓压一个板块。

### 6. 每 3 分钟无条件调一次模型

**现象**：`tick()` → `due(now)` 只看时间（`autopilot.go:412`），不做任何"市场是否有实质变化"的判断。

**证据**：`due()` 实现只有 `now.After(next)`。没有快照指纹、没有涨跌幅阈值、没有持仓变动检测。

**代价**：两重。一是成本，40 轮 × 2.2 万 tokens ≈ 单日 88 万 tokens；二是**质量**——行情几乎没动的时候再问一次模型，得到的往往是"为了给点东西"而生成的边际交易，这正是手续费与滑点的最大来源。

## 四、还有一个结构性短板：智能的"信息上限"被工具带限死了

仓库里已有的数据能力，与AI交易员能用的工具，差距极大：

| 已有能力（已注册 HTTP 接口） | AI交易员能否用 |
| --- | --- |
| K 线（`/quotes/kline`、批量） | ❌ |
| 新闻（`/market/news`） | ❌ |
| 公告、机构研报（`/research/*`） | ❌ |
| 龙虎榜（`/market/billboard`） | ❌ |
| 融资余额（`/market/margin-balance`） | ❌ |
| 期指持仓与会员（`/market/futures-*`） | ❌ |
| 指数与指数序列（`/market/indexes`） | ❌ |
| 市场情绪周期（`internal/marketemotion`） | ❌ |
| 题材库与题材指数（`internal/themeindex`） | ❌ |
| 板块资金流 / 热度 | ✅ |

现在的 6 个工具（`tools.go:83`）：板块资金流、板块热度、板块成分、个股详情、多股对比、历史交易召回。**全是"当下价格结构"，没有一条是"为什么涨"**。

后果在提示词里看得很清楚：`prompt.go:135` 的行情快照只有 OHLC + 成交额 + 涨跌停价。模型被要求判断"事实依据与确认条件"，但它手上的事实只有价格。于是 thesis 天然会退化成"资金流入 + 涨幅居前"这种同义反复。

**这是当前最大的能力缺口，也是最省力的一块**——数据、接口、缓存都在，缺的只是把工具封装出来接进 `Toolbox`。

## 五、升级清单

### P0：直接提升决策质量，改动小、杠杆大

**P0-1 工具带从 6 个扩到 12 个左右（接已有数据层）**

新增建议（括号内为数据来源，全部已存在）：

- `get_kline(symbol, days)` → 返回 MA5/10/20/60、ATR14、量比、近 20 日高低点（`/quotes/kline`）
- `search_news(keyword|symbol, days)` → 标题 + 时间 + 来源，仅摘要（`/market/news`）
- `get_announcements(symbol, days)` → 公告标题与类型（`/research/announcements`）
- `get_billboard(symbol|day)` → 龙虎榜席位与净买额（`/market/billboard`）
- `get_market_context()` → 指数涨跌、涨跌家数、情绪周期阶段（indexes + marketemotion）
- `get_margin_flow(symbol)` → 融资余额变化（`/market/margin-balance`）

约束不变：只读、白名单、结果截断、每步落库可回放。工具从 6 到 12 不改变架构，只改 `Specs()` 与 `Call()` 的分支。

验收：同一标的的调研，模型能引用"公告 + 资金流 + 均线位置"三类证据，而不是只有涨幅。

**P0-2 决策反馈回灌（成本最低、收益最直接）**

`PlanPromptInput` 增加两段：

1. `RecentBlocks []BlockedIntent`：最近 2 小时被拦截的建议，含标的、方向、权重、拦截代码与文案。
2. `LastPlanDiff`：上一轮计划与本轮的差异（哪些标的消失、哪些新增）。

提示词加一节：「## 你最近被拦下的建议（不要原样重复）」，并明确"换个标的可以，原样再提一次只会再被拦一次"。

验收：同一交易日内，`sector.weight` 反复拦截同一标的的次数从多次降到 1 次。

**P0-3 失效条件可执行化**

把 `invalidation` 从自由文本改成**可选结构化条件 + 文本兜底**：

```json
"invalidation": {
  "text": "板块资金流转正或跌破 9.20",
  "price_below": 9.20,
  "sector_flow_positive": "机器人",
  "deadline_days": 5
}
```

守卫每轮对每个持仓检查三类条件（价格 / 资金流 / 时间），任一命中即生成减仓建议并写事件 `EventThesisInvalidated`。文本字段保留，用于人在回放时理解模型当时的想法。

注意：资金流类条件只能**减仓/收紧止损**，不能直接清仓——它比价格信号噪声大得多，直接清仓会把正常波动当成判断失效。

验收：构造一个"价格未触止损但资金流已反转"的持仓，守卫能在下一轮给出减仓。

**P0-4 止损后冷静期（标的级 + 板块级）**

- 单标的：止损出局后 N 小时（建议 4 小时，约一个交易时段）禁止再买。
- 板块级：同一行业大类当日累计 2 次止损，当日禁止买入该行业。

这两条都写在确定性层，不消耗模型、不依赖模型自觉。粒度必须小于 `stop_streak`（账户级），否则一次止损会把全天机会关掉。

验收：构造连续止损场景，第二轮计划中该标的/该板块的买入建议在裁决层被拦，理由明确。

### P1：从「一次判断」升级为「持续管理」

**P1-5 持仓论点跟踪 + 时间止损**

`Position` 增加 `Thesis`、`Invalidation`（结构化）、`EntryRegime`、`EntryConfidence`、`ReviewCount`。

- 每轮做一次确定性"论点复核"：价格是否偏离入场逻辑、板块是否还在、持有天数是否超过计划周期（`Horizon`）。
- 超过 `Horizon` 且浮盈不足（比如 < 2%）→ 时间止损，释放资金。现状是"只要不触价就永远持有"，资金效率被悄悄浪费。

**P1-6 波动率自适应防守线**

用 ATR14 替代固定百分比：

- 移动止损宽度 = clamp(2.5 × ATR%, 3%, 12%)
- 启动门槛 = clamp(1.5 × ATR%, 2%, 8%)
- 止损线距离同理，并继续受 `MaxStopLossPercent` 硬约束

数据来源正是 P0-1 的 `get_kline`，两件事可以一起做。

**P1-7 置信度定价与校准**

- 仓位系数 = 0.5 + 0.5 × confidence（置信度 0 只给一半上限，1 给满），再乘 ATR 调整项。
- 新增 `GET /trading/calibration`：按 confidence 分桶（0.3–0.5 / 0.5–0.7 / 0.7–0.9 / 0.9+）统计真实胜率与均值盈亏，附 Brier 分数。
- 每满 30 笔给出一次"你的 0.9 实际只有 0.55 胜率"的结论，直接写进提示词的经验段。

这是让"自信"变成可验证量的唯一办法。没有校准，`confidence` 就是让模型自我感觉良好的字段。

**P1-8 记忆自动注入与衰减**

现状：记忆只能由模型**主动**调用 `recall_trades` 才能拿到；存的是平仓交易；没有衰减。

改法：
- 计划前按 `regime + 当前候选行业` 自动检索 3–5 条最相关记忆，直接写进提示词（"你在类似环境下买过这个板块两次，都止损了"）。
- 调研结论也入库（现在只存交易）："机器人板块 5 日净流出 74 亿"这种结论，下一轮不该重新查一遍。
- 记忆按时间衰减权重，30 个交易日前的市场环境与今天基本无关。

### P2：工程与评估，决定它能不能持续变好

**P2-9 变化检测与安静模式**

- 计算快照指纹（候选池 Top10 + 持仓标记 + 市场 regime + 各持仓涨跌幅取整）。
- 指纹未变且距上次计划 < 30 分钟 → 本轮跳过模型，只跑撮合与防守。
- 预期把有效模型轮次从 40 降到 8–12，token 成本降 60% 以上，同时减少边际交易。

这是**省钱与提质同时发生**的少数改动，建议优先于任何新增功能。

**P2-10 撮合真实化**

现状 `broker.go:105` 按 `quote.Price` 全额成交。改为：

- 滑点：按成交额分档（< 5000 万 → 0.3%，5000 万–3 亿 → 0.15%，> 3 亿 → 0.05%）。
- 流动性上限：单笔不超过当日成交额的 0.5%，超出则部分成交。
- 涨跌停排队：触及涨停价的买单不成交（模拟排队失败）。

不做这条，所有业绩数字都系统性偏乐观，后续无论怎么优化策略都无法判断是否真的变好。

**P2-11 策略回放沙盘**

`timeline` 是运维回放，回答"那天发生了什么"；还缺一个**策略回放**，回答"如果换一版提示词/规则，那段时间会怎样"。

最小可用版本：固定历史 K 线序列 + 固定快照构造器，按时间推进重放 `RunPlanSync` 与裁决，不写账本。用来在改提示词之前先看差异，而不是直接上线观察。

**P2-12 事件驱动临时轮次**

`CycleTriggerEvent` 已定义但全仓未使用。接上三类触发器：

- 持仓单日跌幅 > 5%（早于止损线，提前反应）
- 所属板块资金流转负
- 指数 15 分钟内跌 > 1.5%

触发即插一次临时轮次，但仍受全部闸门约束（熔断、时段、配额）。注意设冷却，否则事件密集时会变成高频调用。

## 六、不建议做的

- **多智能体辩论（多方/空方/裁判）**：成本 ×3，而当前的确定性规则包已经承担了"风控官"角色。真要做红队复核，只对高集中度计划做一次，且必须有明确的否决权边界，否则会变成"两个模型互相说服"。
- **让模型直接输出股数与金额**：现在"只输出权重、股数由系统换算"的设计是对的，别退回去。
- **放开原生工具调用**：`DisableTools: true` + Go 侧白名单执行是当前可回放性的基础，换掉的收益远小于失去的审计能力。

## 七、建议的交付批次

| 批次 | 内容 | 理由 |
| --- | --- | --- |
| 第一批 | P2-9 变化检测 + P0-2 反馈回灌 | 都是小改动，一个省钱一个提质，且互不依赖 |
| 第二批 | P0-1 工具扩容 + P1-6 自适应止损 | 同一批数据依赖，一起做只需接一次 K 线 |
| 第三批 | P0-3 失效条件 + P1-5 论点跟踪 | 后者依赖前者的结构化条件 |
| 第四批 | P0-4 冷静期 + P1-7 置信度定价 | 都是风控层，改动集中 |
| 第五批 | P2-10 撮合真实化 + P2-11 回放沙盘 | 评估基础设施，做完才能真正衡量前四批的效果 |

前两批做完，系统的"聪明程度"会有肉眼可见的变化；第五批做完，才有资格说"这套东西在变好"。
