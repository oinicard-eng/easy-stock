# AI交易员（模拟盘）

## 定位

AI交易员是在 easy-stock 内新增的**研究与执行分离**模块：大模型给出交易判断，Go 代码负责取数、算股数、风控校验和记账，最终由用户确认后才进入本地模拟撮合。

它和系统原有能力的边界：

| 能力 | 是否具备 |
| --- | --- |
| 生成标的、方向、权重、止损与失效条件 | 具备（LLM） |
| 计算股数、费用、涨跌停区间 | 具备（Go，确定性） |
| 单票/总仓位/单笔风险/T+1 校验 | 具备（Go，确定性） |
| 本地模拟成交、持仓与现金账本 | 具备 |
| 接入券商、发出真实委托 | **不具备**，接口预留 |

## 为什么模型不碰数字

如果把行情和账户余额交给模型自行组织，模型会编造价格、算错整手、超买现金。因此提示词里只放三样东西：行情快照、账户状态、风控阈值；模型只输出 `target_weight_percent`（目标权重）与 `stop_loss_price`（止损价），股数由 `BuildOrders` 依据账户总资产与限价换算，并按 100 股整手向下取整。

模型越权的情况全部在确定性层被拦住：

- 标的不在本次行情快照内 → 拒绝；
- 限价超出涨跌停区间（主板 10%、创业板/科创板 20%、ST 5%、北交所 30%）→ 拒绝；
- 单票权重超过上限、加仓后合并权重超限 → 拒绝；
- 买入缺止损、止损价高于买入价、止损距离超限 → 拒绝；
- 按股数折算的止损亏损超过单笔风险上限 → 拒绝；
- 卖出超过可卖数量（T+1 当日买入不可卖）→ 拒绝；
- 可用资金不足 → 先按整手缩减，仍不足则拒绝。

被拒绝的建议不会被静默丢弃：订单以 `rejected` 状态保留并附原因，前端逐条展示，方便判断模型是否在系统性越界。

## 代码结构

```text
backend/internal/trading
  types.go     领域模型、风控阈值、状态机、门控与对账结构
  store.go     SQLite 账本：账户 / 持仓 / 计划 / 订单 / 成交（单事务记账）
  ledger.go    挂单资金冻结：Reserve / Release / 对账 / 账户总闸
  risk.go      BuildOrders：模型建议 → 可执行订单 + 确定性校验
  prompt.go    交易计划提示词（事实、约束、输出 schema）
  decode.go    JSON 提取（容错代码块与前后解释文字）
  broker.go    Broker 接口 + PaperBroker + 实盘占位
  service.go   计划生成（异步）、执行、挂单撮合、账户视图、门控、对账
```

执行链路：

```text
前端 POST /api/v1/trading/plans
  -> 创建 running 计划并立即返回
  -> 后台：拉行情 + 账户 → 组装提示词 → Agent Service（沙箱、无工具）
  -> ParseDraftPlan → BuildOrders（风控）→ 落库为 draft
用户确认 POST /plans/{id}/execute
  -> PaperBroker 按最新价撮合 → ApplyFill 单事务更新订单/持仓/现金/成交
```

计划生成使用 `agent.PromptOptions{Sandbox: true, AutoApprove: true, DisableTools: true}`：一次性临时沙箱、不加载用户 MCP/Skills、不开放终端与文件工具。没有工具是刻意选择——数据已经由后端注入，开放工具只会引入不可复现的外部输入和额外延迟。

## 模拟撮合规则

- 限价买入：现价 ≤ 限价才成交，成交价取现价；否则保持挂单。
- 限价卖出：现价 ≥ 限价才成交。
- 市价单：按现价成交，但仍校验涨跌停区间。
- 无有效行情：保持挂单，不猜测成交。
- 费用：佣金万分之 2.5（最低 5 元）+ 过户费万分之 0.1，卖出加印花税万分之 5。
- T+1：买入当日 `available_quantity = 0`，次日由 `RolloverAvailable` 解锁。

## API

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/v1/trading/account` | 账户（含冻结/可用）、持仓、门控、执行通道与限额 |
| POST | `/api/v1/trading/account/reset` | 重置模拟盘资金（清空持仓/订单/计划/门控） |
| GET | `/api/v1/trading/control` | 读取账户总闸（暂停买入 / 全部停止） |
| POST | `/api/v1/trading/control` | 修改总闸；`kill_switch` 会强制 `pause_buying` |
| POST | `/api/v1/trading/reconcile` | 对账冻结额与挂单，`?repair=true` 时回写 |
| GET | `/api/v1/trading/market` | 市场状态、广度指标、行业强度、仓位预算 |
| GET | `/api/v1/trading/universe` | 候选池、入选理由、排除项 |
| POST | `/api/v1/trading/plans` | 生成计划，返回 `running` 状态；`watchlist` 留空即自动选股 |
| GET | `/api/v1/trading/plans/{id}` | 轮询计划状态与订单 |
| GET | `/api/v1/trading/plans` | 历史计划 |
| POST | `/api/v1/trading/plans/{id}/execute` | 人工确认后执行 |
| POST | `/api/v1/trading/plans/{id}/reject` | 放弃计划并撤销挂单、释放冻结 |
| POST | `/api/v1/trading/match` | 对挂起订单重新撮合 |
| POST | `/api/v1/trading/orders/{id}/cancel` | 撤销单笔挂单并释放冻结 |

数据文件默认位于用户数据目录的 `trading.db`，可用 `A_STOCK_TRADING_DB` 覆盖。

## 前端

侧边栏「AI交易员」工作台（`frontend/src/components/TradingWorkspace.tsx`）：

- 账户概览：总资产、可用资金、持仓市值、浮动盈亏；
- 市场环境：状态、仓位预算、上涨/下跌家数、涨跌停数、涨幅中位数、成交额，可展开看行业强度与判断依据；
- 候选池：系统自动选出的标的、评分、风险大类，可展开看每只的入选理由与被排除项；
- 计划生成：关注池（留空即自动选股）、交易者画像、计划周期、补充材料；
- 计划详情：市场状态、摘要、风险提示、逐笔订单与拒绝原因、校验问题；
- 执行确认：弹窗列出待执行订单，明确提示不会触达券商；
- 持仓与挂单：查看可卖数量、撤销挂单、加入关注池；
- 历史计划：最近 10 份，可回看当时的行情快照。

## 阶段规划

**P1（已完成）**：模拟盘账本、LLM 计划生成、确定性风控、人工确认执行、手动撮合、前端工作台。

**P2.1（已完成）**：账本加固——挂单资金冻结、可用资金口径统一、在途挂单计入单票权重、冻结对账、账户总闸（暂停买入 / 全部停止）、`decision_id` 追溯。详见 [trading-agent-ledger.md](trading-agent-ledger.md)。

**P2.2（已完成）**：市场认知与候选池——全市场广度指标、五档市场状态与仓位预算、硬性排除、五维打分（倒 U 型动量）、分散约束（大类 + 板块）、入选理由与排除项、自动选股入口。全部确定性计算，不调模型。详见 [trading-agent-universe.md](trading-agent-universe.md)。

**P2.3**：决策层与守卫。模型只输出方向与权重，守卫层校验，裁决层输出可执行动作，仍不自动下单。

**P2.4**：循环编排与自动执行。定时 + 事件触发，持仓管理先于模型决策，双熔断（日亏 3%、连续 3 笔止损）。

**P2.5**：可观察性与复盘骨架。决策日志、循环视图、复盘记录。

**P3**：持仓生命周期。防守线（只升不降）、分级止盈、冷却期、可卖数量冻结。

**P4**：复盘与经验。枚举维度归因、样本下限 30、幂等写入。

**P5**：实盘通道。实现 `Broker` 接口（QMT / Ptrade / 富途等），补齐凭据管理、二次确认、单日限额、熔断与审计日志。**在实盘通道实现之前，系统不存在任何真实下单路径。**

## 已知限制

- 科创板 688 的实际申报规则为 200 股起、以上按 1 股递增，当前统一按整手处理。
- 行情来自系统既有实时接口，非逐笔成交；模拟成交价取最新价，不含滑点与盘口深度。
- 计划生成是异步单任务，同一时刻只允许一份计划在生成。
- 模型输出仍需人工核对；风控只能约束数值边界，不能判断逻辑是否成立。
- **可卖数量尚未冻结**：同一批股票可被两个卖单同时占用，第二笔在成交时因可卖不足被拒。不会算错账，但会出现「挂单看着能卖、实际卖不掉」。P3 补 `reserved_quantity`。
